# step1: エッジマス/フィラーマス分類のベンチマーク

ASCII アート変換パイプラインにおいて、各マス(セル)を「エッジマス」と「フィラーマス」に
分類する方式を探求するための、第一段階としての採点(ベンチマーク)環境。

## 背景

- 本プロジェクト (BrowserMoji) は「前処理 → 縮小(セル化) → 特徴量計算 → 文字選択 → 描画」の
  パイプラインを持つ (docs/architecture.md)。
- 文字選択方式の探求 (explore-2) に先立ち、まずセル分類の良さを数値で測れるようにする。
- 分類の良さは、人手でアノテーションした採点用画像との一致率で評価する。

## 採点用画像

`data/` 内の静止画 13 枚 (face1-3, high_contrast1-4, room1-3, scene1-5) を
ペイントソフトで色分けしたもの。解像度は元のまま。

色の意味:

| 色 | 意味 | 正解ラベル |
|---|---|---|
| 赤 | エッジマスだと認識してほしいマス | 1.0 |
| 黄 | どちらでもいいマス (髪・テクスチャ等) | 0.5 |
| 無地 | フィラーマス | 0.0 (ネガティブとして数える) |

注意点:

- 筆は太め (フル解像度で 150〜200px) で、赤/黄ストロークは真のエッジ線を
  太く膨らませた形になっている。採点側でこの太さを吸収する工夫をしている (後述)。
- JPG 再保存の影響で、色は完全な (255,0,0) 等ではない。
  score.py は許容幅付きの色判定 (赤: R>180 & G<80 & B<80、黄: R>180 & G>180 & B<100) を使う。
- 元画像は `work/orig/` にあり、予測器はこちらを入力とする
  (アノテーション色を予測器に見せないため)。

sample.mp4 のフレームはぼやけているため不使用と判断した。
抽出スクリプト (src-frames/) は参考として残してある。

## グリッド仕様

本番アプリに合わせる (src/config.ts, src/pipeline/grid.ts):

- columns = 100 (固定)
- featurePx = 16 → 前処理後の特徴量画像の幅は 100×16 = 1600px
- セルは正方形 (16×16px)、行数は画像アスペクト比から自動計算

採点も同じく、画像を幅 1600px にリサイズし、16×16px を 1 セルとして扱う。

## 採点方法 (score.py)

各セルの正解ラベル:

- セル内の赤ピクセル率 ≥ 50% → 1.0
- セル内の黄ピクセル率 ≥ 50% → 0.5
- それ以外 (無地) → 0.0
- 赤・黄が混在するセルは赤を優先

3 種の指標を併記する。

### 指標1: F1_cell (セル多数決 F1)

黄を 0.5 重みのソフトラベルとして precision / recall / F1 を計算。

- precision = Σ min(正解ソフトラベル, 予測) / Σ 予測
- recall    = Σ min(正解ソフトラベル, 予測) / Σ 正解

### 指標2: skel_P / skel_R / skel_F1 (スケルトン基準, 主指標推奨)

赤マスクを細線化 (skeletonize) して「真のエッジ線」とみなす。
筆が太くても中心線はエッジ上に残るため、太筆・塗りずれの影響を受けにくい。

- skel_R: スケルトンセルのうち、予測エッジが自分または 8 近傍にある割合
- skel_P: 予測エッジセルのうち、赤∪黄マスクを brush_dilate(3) セル分膨張した
  領域に入る割合 (膨張は太筆の幅を吸収する)

### 指標3: dist_decay (距離減衰, 補助)

予測エッジセルと赤マスクの距離 d (セル単位) に対する exp(−d²/2σ²) の平均 (σ=2)。
完全一致でなくても近ければ部分点が入るため、分類器チューニング中の
滑らかなフィードバックに使う。

  → 分類器改善の最初の課題は precision 向上になりそう。
