# explore-1 総括: エッジマス/フィラーマス識別の探求

BrowserMoji(カメラ映像→日本語AA)の新しい文字選択方式の基盤として、
画像の各セルを「エッジマス(線文字)」「フィラーマス(濃淡文字)」に分類する手法を
2026-11 に探求した際の記録。

## 目的

AA 変換において、各マス(セル)を線で表現するか濃淡で表現するかの振り分けが必要。
エッジマスは「直線状・曲線状に並んでいる」ことが望ましく、2D 的な閉領域の面として
検出されるのは望ましくない(→ 問題3)。

## 経緯と各ステップの要点

### step1: エッジ検出フィルタの探索
- data/ の静止画 16 枚に sobel / laplacian / canny を適用し、前処理
  (ヒストグラム平坦化 / CLAHE / ガンマ)の比較も実施
- **結果: canny を採用**。ソーベル系は階調はあるもののノイズが多く、canny が
  背景ノイズに強く輪郭を拾える
- 発見した canny の 3 つの問題:
  1. 輪郭が途切れ途切れになる
  2. 白いごま塩ノイズが混ざる
  3. エッジ密集領域が面(白ブロック)になる ← 以後の主課題

### step2: canny の問題対策として 3 案を比較
- 甲: canny 改良(bilateral 前段 + 自動閾値 + 孤立点除去)
- 乙: Edge Drawing (EDPF) — opencv-contrib
- 丙: XDoG / DoG 線画化
- 結論: **EDPF の輪郭連続性が最大の強み**(途切れに強い)が、テクスチャ領域での
  過剰発火と暗部のアンダーセグメントが弱点。XDoG は線ではなく階調付き線画で、
  フィラー側の階調表現への転用余地あり
- 問題3(密集領域の面化)はピクセルレベルの手法では解決しないと判明

### step3: セル単位の振り分け方式を比較
エッジマス/フィラーマスの分類を 4 案で比較(16px セル、白セル/グレー塗りの可視化):
- 案1 エッジ率閾値: 問題3がそのまま再現され全滅
- 案2 **PCA 形状判定**(セル内エッジ画素の主軸分析で「細長さ」を判定): テクスチャを
  フィラーに落とせて唯一問題3に効いたが、緩く曲がる輪郭を取りこぼす
- 案4 EDLines 線分のセルラスタライズ: 線状性は構造的に保証されるがテクスチャに弱い
- 案5 セル NMS 尾根: 階調系(xdog)と相性が良いが、二値ソースには機能しない
- ユーザー評価: pca-canny / nms-canny / edl-bilat が候補に

### step4: 持ち上げた 3 候補の改善
- 案A 共通後処理(clean=孤立セル除去 / closing / スケルトン化):
  - **clean は全候補で有効**(ノイズだけ落として輪郭を残す)
  - **スケルトン化は不採用** — 大きな連結塊を骨架化するとボロノイ様の幾何網
    アーティファクトが発生
  - closing は効果軽微
- 案B PCA 多スケール化: 16px 線率 > 50% は細線を拾えない構造的欠陥あり。
  4px 小セル線率 25〜30% が実効しきい値との知見を得た
- 案C 方向一貫性フィルタ: 方向差 ≤30° で隣接セルを接続→チェーン化。
  テクスチャ除去は劇的だが曲線輪郭に過剰に厳しい(45° 緩和の余地)
- 案E EDPF 改善: coherent(セグメントの真っ直ぐさフィルタ)のみテクスチャ発火を
  大幅減。CLAHE / 勾配閾値低下は暗部をむしろ悪化させる

### step5: 統合パイプライン
知見を統合した 7 バリアントを比較し、
**det-16px PCA → 方向チェーン θ45° → 孤立セル除去(B2)** を推奨。
EDL は「直線的なテクスチャ自体」を拾う構造的弱点があると判明。
暗部(test-frame)では canny 系が全滅(入力エッジが 49px のみ = 入力側の問題)。

### step6: ベンチマーク導入(explore-2/step1 と連携)
- explore-2/step1 の手描きアノテーション GT(赤=エッジ必須 / 黄=どちらでもいい /
  無地=フィラー、15 枚)と score.py を利用
- 本番グリッド仕様(幅 1600px、cols=100、16px セル)で 5 予測器を比較
- 初回は 1280px 基準のしきい値がそのままのため recall が崩壊
  → **step6b でしきい値再調整**(エッジ率 0.1→0.04、MIN_EDGE_PX 15→5、
    baseline quantile 0.85→0.80)
- それでも baseline(Sobel 上位 15% セル)が skel_F1 首位のまま
  = 素の recall 戦略が強く、提案手法は precision を買っている(pca/b2 の
  P_cell 0.61〜0.66 vs baseline 0.467)

### step6c: 細筆アノテーション GT
ユーザーが「最低限検出してほしい線」のみを細筆で塗った GT(work-thin/ 15 枚)を
追加し、スパース・recall 志向 GT での再採点。Fβ 指標を導入(--beta)。
- skel_F1: baseline 0.366 > pca 0.273 …だが skel_R(recall)では **pca 0.722 が全手法最高**
- スパース GT では skel_P/P_cell の絶対値を過小評価し「recall を確保しつつ精度を
  落とさないか」で見るのが妥当

### step7: step3 候補(pca-canny / nms-canny / edl-bilat)の再検証
パラメータスイープ + overlay 目視:
- **pca-canny が実質の勝者**: MIN_EDGE_PX=5 / σ2σ1<0.35 / エッジ率≥0.02 で
  skel_F1 0.371(baseline 0.366 抜き)、skel_R 0.804、dist_decay 最高
- **edl-bilat の高スコア(0.696)は塗りつぶしアーティファクト**: JPEG ブロック
  ノイズ由来のセグメントが全域を埋め、予測セル 77% という過剰予測で skel_F1 が
  水増しされていた。step3 の「見た目良し」は GT 重ね見をしていなかった錯覚の可能性
- nms-canny は線状にならず点在するだけ。最弱のまま

### step8: pca-canny の精度改善
確定候補に 3 ステージを追加して比較:
- +clean / +chain / +chain+clean / +stripe(横縞抑制) / +stripe+clean
- **数値(skel_F1)重視なら base のまま**。追加ステージは全件 GT 細線を削って
  マイナス(clean/chain は非推奨)
- **視覚品質重視なら +stripe**(skel_F1 −0.013 の代わりにタワー横縞のブロック
  誤爆を顕著に抑制)
- 水面反射の縁は本物の輪郭と同質(方向・連結性とも)で、セル分類段階では
  原理的に区別不能 → 次段(文字選択/階調)側で吸収する課題

## 最終確定候補

```
前処理:  グレースケール → bilateralFilter(d=9, σColor=75, σSpace=75)
エッジ:  Canny(low=50, high=150)
セル分類: 16px セル内エッジ画素 ≥5 かつエッジ率 ≥0.02
          かつ PCA σ2/σ1 < 0.35(細長い=線)
[オプション] 横縞抑制: |gy|/(|gy|+|gx|) > 0.60 かつ主軸水平(≤30°)の帯セルは
          帯内で最もエッジ強度の高い 1 行のみ残す
```

- 数値重視ならオプションなし、視覚品質重視なら横縞抑制を入れる
- **未解決の課題**:
  - 暗部入力での canny 全滅(入力側の問題。CLAHE/閾値では悪化)
  - 水面反射など本物と同質の擬似輪郭(文字選択段階の階調で吸収する想定)
  - EDL 系の再設計(現状のままでは JPEG ノイズに弱い)
