# D-003: 生成物の契約③ — AppConfig の初期項目

- 状態: 🔶（仮決め）
- 関連: architecture.md §1（設計原則 2）, requirements.md §7.2

## 背景

architecture.md の設計原則 2 より、調整可能な値はすべて 1 つの設定オブジェクト（AppConfig）に集める。UI・保存・実験が同じ設定を読むため、フィールド名と初期項目を先に固定する。

## 選択肢

1. **最小セットから始めて必要に応じて追加する**
2. 想定される全項目（カラー・セグメンテーション含む）を最初から入れる
3. 項目を Map 的な key-value にする（型保証が弱い）

## 決定

AppConfig の初期項目は次の 7 つとする:

| フィールド | 内容 |
|---|---|
| `columns` | 列数（行数は画面比から自動計算） |
| `contrast` | 輝度の階調の強さ |
| `edgeThreshold` | エッジとして扱う勾配のしきい値 |
| `edgePriority` | エッジ文字への置き換えのしやすさ |
| `invert` | 白黒反転 |
| `charset` | 使用する文字セット |
| `showFps` | デバッグ用 fps 表示（P-3） |

カラー関連の項目は **F-10 採用時に追加する**（Renderer の color 引数の契約はarchitecture.md §2 に既にある）。

## 理由

- §7.2 の M 項目（解像度・コントラスト・エッジ・白黒反転）と P-3 を確実に満たす最小構成
- 未採用機能（カラー・F-17 など）の項目を先に入れると、意味のない既定値が乱立する。必要になった時点で追加する方が契約が汚れない
