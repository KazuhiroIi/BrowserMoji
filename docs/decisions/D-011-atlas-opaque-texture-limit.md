# D-011: アトラスを不透明画像にし、テクスチャ幅上限を超えさせない

- 状態: 🔒（確定）
- 関連: architecture.md §5, D-008, D-010, P-3

## 背景（実機で発生した不具合）

実機テスト（OPPO A5 2020・Android Chrome・Tailscale 経由 HTTPS）で、「開始」直後から
画面が**完全な無地の黒**になり何も映らない不具合が発生した。設定で Canvas 2D に切り替えると
ASCII 出力が現れるため、原因は WebGL2 の描画に限定できた。fps オーバーレイは表示されるが
avg/min とも 0.0 fps・各ステージ 0.0 ms だった（フレーム間隔が 1 秒を超え、fps 窓が
毎フレーム立て直されていたため）。

原因は次の連鎖:

1. D-010（EXP-3）で文字セットを 62 文字に増やした結果、ダミーアトラスの canvas が
   62 グリフ × 96px = **5952px 幅**になった（EXP-1 実機計測時は 13 グリフ = 1248px）
2. OPPO A5 2020 の `MAX_TEXTURE_SIZE` は **4096**（実測。修正後の fps オーバーレイ表示
   `maxTex4096` で確認）を超えていたため、`texImage2D` が `INVALID_VALUE` で
   **サイレントに失敗**していた（`gl.getError()` の確認がなかった）
3. 転送に失敗したテクスチャは「不完全テクスチャ」になり、GL の仕様上サンプル値は
   **不透明黒 (0,0,0,1)** を返す
4. フラグメントシェーダは `mix(uBg, tex.rgb, tex.a)` で背景色と alpha を合成していたため、
   `mix(白, 黒, 1) = 黒` となり、画面全体を覆う 1 枚のクアッドが**全画面を真っ黒に塗った**

Canvas 2D 方式は同じ 5952px の canvas を `drawImage` の転写元として使えている（canvas の
サイズ制限とテクスチャのサイズ制限は別物）。ヘッドレス / デスクトップ GPU では上限が
8192〜16384 で転送が成功するため e2e では再現しない。同じ端末で EXP-1 の WebGL2 計測が
成功していたのは、当時のアトラスが上限内だったから。

検証（ヘッドレス Chromium / SwiftShader, `MAX_TEXTURE_SIZE` = 8192）:

- 上限内の canvas の転送 → `getError() == NO_ERROR`、サンプル値は白
- 上限超過（8192 × 2）の canvas の転送 → `INVALID_VALUE (1281)`、サンプル値は**不透明黒**

## 選択肢

1. **アトラスを不透明にする + 上限に収まるようセル幅を縮める + 転送失敗を検知して Canvas 2D へフォールバック**
2. アトラスを縦タイル化（複数行レイアウト）し、シェーダでタイル座標を計算する
3. 転送失敗時のみ Canvas 2D にフォールバックする（アトラスは透明のまま）

## 決定

1. を採用する。

- **アトラス canvas は背景色まで塗った不透明画像にする**。WebGL2 のフラグメントシェーダは
  `outColor = vec4(tex.rgb, 1.0)` でよく、alpha と背景色の合成（`mix`）をシェーダに介さない。
  不完全テクスチャ以外の「端末ごとの canvas alpha の扱い差」による黒画面も一掃できる
- **アトラスは `MAX_TEXTURE_SIZE` に収まるよう 1 セル幅を縮めて構成する**
  （`AtlasProvider.getAtlas(cfg, maxAtlasWidth)`。62 グリフなら 4096px 上限で 66px セル）。
  出力セルは多くても数十 px なので縮小は見た目にほぼ影響しない。上限が極端に小さく
  最小セル幅（16px）でも収まらない場合は例外とし、Canvas 2D にフォールバックする
- **`texImage2D` / `texSubImage2D` / draw の後で `gl.getError()` を確認する**。エラーを
  検知したら描画を止め（黒で塗らない）、context lost と同じ経路で Canvas 2D に
  フォールバックする
- fps オーバーレイに WebGL2 の診断情報（`maxTex` / GL エラーコード / broken）を出す。
  1〜5 秒のフレーム間隔は「重いが動いている」状態として窓に記録し、実機の低 fps が
  0.0 表示にならないようにする（P-3 の計測性の改善）

## 理由

- 黒画面の直接原因（不完全テクスチャの不透明黒サンプル）を**構造的に排除**できる
  （3 を併置するので、想定外の失敗でも黒画面ではなく Canvas 2D への切替で見た目が保たれる）
- 2（タイル化）はシェーダ変更が必要で、将来の本物アトラス資産（D-002 の PNG 契約）への
  移行時に制約を増やす。1 はダミーアトラスの生成パラメータとシェーダ 1 行で済み、
  Canvas 2D 側も変更不要（基準画像との差分 0.000% を確認済み）
- テクスチャ幅上限は端末依存のため、上限を超えさせない設計は本物アトラス資産
  （Python トラック生成。文字数がさらに増える可能性）にもそのまま引き継げる

## 検証

- `e2e/texture-limit.spec.ts` を新設。getContext を Proxy でラップして
  `MAX_TEXTURE_SIZE` を偽装し、実機と同じ条件をヘッドレスで再現する
  - 4096: WebGL2 のまま描画が続くこと（一色でないこと）
  - 512: Canvas 2D にフォールバックして描画が続くこと
- 既存の `correctness.spec.ts`（基準画像比較・2 方式差分）はすべて合格
  （不透明化による出力変化は ±1 LSB 未満で基準に影響しない）
- **実機再確認（OPPO A5 2020・修正後）**: WebGL2 のまま ASCII が表示されることを確認
  （fps オーバーレイ `cols 100 / webgl2 / maxTex4096`）。100 列での実測は
  avg 0.4 fps / feat 2543.9 ms / pre 91.1 ms / read 52.8 ms / sel 5.6 ms / draw 9.5 ms
  （cam 24.8 fps）。Canvas 2D 切替時は avg 0.3 fps / draw 243.5 ms で、
  WebGL2 の draw の速さ（1 draw call）が実機でも再確認された

## 持ち越し

- 特徴量計算の CPU 負荷は D-009 適用（076886d）で約 500〜1000 倍になっており、
  実機（OPPO A5 2020・100 列）の実測でも feat 2543.9 ms / avg 0.4 fps と
  数秒/フレームになっている（開発機でも 1.2〜1.4 fps）。特徴量計算の
  GPU 移行（exp-1.md 持ち越し事項 1）とモバイル向け既定値の見直しは別途対応する
