# D-010: 文字セットは記号系フィラー（density 27 段階＋line 35 文字）に絞る。ブロック文字の使用を許可する

- 状態: 🔒（確定）
- 関連: requirements.md §8（T-1 改訂、T-4 確定、T-5、Q-7 解決）, architecture.md §10（EXP-3）, EXP-2 / D-009, EXP-3, D-002（特徴量テーブル契約）

## 背景

EXP-3（docs/experiments/exp-3.md）で、文字セット候補 5 群
（density 16 / line 35 / hiragana 71 / katakana 71 / kanji 19、計 212 文字）の
シートをユーザーが評価した。結果:

- density 群は濃い側が粗い（0.15 〜 0.64 に隣接差 +0.12〜+0.16 の谷）
- line 群の向きのバリエーションは十分（水平・垂直・45°/135° が揃う）
- かな・漢字を濃い領域のフィラーに使うには濃度が足りない
  （かな最大 0.261、漢字最大 0.331）
- フィラーは記号系（四角など）で完結させたい。かな・漢字は無しでよいかもしれない

一方で EXP-2 / D-009 により文字選択は**方式 A（輝度 → 濃度文字＋エッジ線文字）**
を採用済みで、方式 A が使うのは density 群と line 群の直線サブセットのみ。
かな・漢字は不採用の方式 B（25 次元最近傍）の候補だった。

追加候補の濃度は scan.py（atlas.py と同一の手順）で 79 文字を計測して比較した。

## 選択肢

1. **フィラーを記号系に絞り、ブロック要素の追加を許可する**
2. フィラーを記号系に絞るが、ブロック要素は使わない（T-1 を維持）
3. かな・漢字を残したまま濃度ランプを増強する

## 決定

- **採用セット（プリセット `all`）= density（27 文字）＋ line（35 文字）の計 62 文字**
- density 群に 11 文字を追加: `▒`(0.189) `▣`(0.224) `▃`(0.312) `◐`(0.350)
  `▄`(0.437) `▀`(0.500) `▅`(0.562) `▆`(0.687) `▛`(0.719) `▇`(0.812) `█`(0.937)
- **T-1 を改訂する**（requirements.md v0.4）: 「ブロック文字（▀▄█ など）は使わない」
  →「グリフアトラス描画の等幅セル内であれば、ブロック文字を濃度フィラーに
  使ってよい」
- かな・漢字の 3 群は採用セットから外す。ただし定義は charset.py に残し、
  方式 B の再評価用プリセット `b`（全 5 群・223 文字）として温存する
- line 群は現状維持。エッジ用文字の追加はユーザーの検討事項として保留（T-5）

## 理由

- **方式 A の構造上、かな・漢字は使われない**: 方式 A は濃度記号（density 群）と
  線記号（line 群）のみを選択する。かな・漢字を採用セットに残すメリットがなく、
  アトラスと特徴量テーブルのサイズだけが増える
- **非ブロックの記号では濃度の上限が ■（0.640）**: 計測した 79 候補のうち、
  0.48〜0.63 と 0.64 超（黒側）に存在するのはブロック要素のみ。ユーザー評価の
  「濃い側が足りない」を解決するにはブロック要素が事実上必須
- **ブロック要素は幾何学的に等間隔**: Noto Sans JP の下棒・左棒・網かけは
  1/8 刻み（▁0.062 → █0.937、ほぼ 0.125 刻み）で、濃度ランプとして理想に近い
- **T-1 の懸念（グリッド崩れ）はアトラス描画で解消済み**: T-1 の意図は
  端末フォント差による等幅グリッドの崩れ（N-5）の防止。グリフアトラスは
  セル幅を固定して描画するため、ブロック文字の字幅に依存しない（T-2 は維持）
- **半角英数字・半角カナは引き続き使わない**（T-1 の残りの部分は維持）

## 影響

  （all = density+line、b = 全 5 群）

- requirements.md を v0.3 → v0.4 に更新（T-1 改訂、T-4 確定、Q-7 解決）
