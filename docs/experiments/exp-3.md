# EXP-3: 文字セット候補の比較（T-4 / Q-7）

状態: **確定**。シートの目視評価（ユーザー）と濃度の計測（scan.py）により、
採用文字セットを決定した（docs/decisions/D-010-charset-symbols.md）。

- 関連: architecture.md §10（EXP-3）、requirements.md §8（T-1 改訂、T-4）、docs/decisions/D-002（契約①）、D-009（方式 A 採用）
- 実装: `tools/prototype/charset.py`（採用セット定義）、`sheet.py`（シート生成）、`scan.py`（追加候補の計測）

## 目的

文字セット候補（5 群）を Noto Sans JP Regular で描画したシートを確認し、

- 濃淡の階調の幅が十分か（density 群の段階が視覚的に均等か）
- エッジ表現の質（line 群の向きのバリエーションが十分か）
- かな・漢字を混ぜたときの質感と濃度の隙間（階調の谷）の有無

を見て、採用する文字セットの範囲を打ち切り決定する。

## 文字セット（決定）

採用セット（プリセット `all`）は **2 群・計 62 文字**。Noto Sans JP Regular
（OFL-1.1）にすべて収録されることを生成時に確認済み。

| 群 | 文字数 | 濃度の計測値 | 内容 |
|---|---|---|---|
| density | 27 | 0.000（全角スペース）〜 0.937（█） | 濃度段階。記号 16 文字＋追加 11 文字（▒▣▃◐▄▀▅▆▛▇█） |
| line | 35 | 0.029 ─ 〜 0.219 ╋ | 線・枠記号（向きのバリエーション） |

方式 A のエッジ置換は、向きが一意でない角・T 字を除いた「まっすぐな線」
サブセット（`STRAIGHT_LINE_CHARS`、12 文字）を使う（T-5 の調整に相当）。

かな・漢字の 3 群（hiragana 71 / katakana 71 / kanji 19）は、方式 A では
不使用（フィラーは density 群のみ、エッジは line 群のみ。D-009）のため
採用セットから外した。方式 B の再評価用に、プリセット `b`
（全 5 群・223 文字）として定義だけ温存する。

フォント実体はリポジトリにコミットしない（`.gitignore` で
`tools/prototype/fonts/` を除外。ライセンスは tools/prototype/README.md に記録）。

## 生成コマンドと出力

```sh
cd tools/prototype
uv run python atlas.py       # → out/assets/{atlas.png,features.json}（all = 62 文字）
uv run python sheet.py       # → out/charset/{density,line}.png
uv run python scan.py        # 濃度フィラーの追加候補を計測 → out/charset/proposal.png
# かな・漢字のシートも見る場合（b プリセットで再生成し、最後に all に戻す）
uv run python atlas.py --charset b && uv run python sheet.py --charset b
uv run python atlas.py && uv run python sheet.py
```

シートは群ごとに、`charset.py` の定義順（追加文字は計測濃度順に挿入）で並べる。
特徴量テーブル `out/assets/features.json`（schemaVersion 1、charCount 62、cellPx 64、
featurePx 16、dir8 = 8 方向、region4 = 4×4）の `chars[]` は
`id / char / group / subgroup / density / dir8 / region4` のキーを持ち、
契約①（D-002）と一致する。

## 評価結果（チェックリスト）

シート 5 群の目視評価（ユーザー）と、features.json の濃度計測値の分析（エージェント）:

- [x] density 群の段階が視覚的に均等か → **当初の 16 文字では不十分**。
      0.15 〜 0.64 に大きな谷（隣接差 +0.12〜+0.16）があった → 11 文字の追加で解決
- [x] line 群に水平・垂直・斜め（45° / 135°）の線が揃っているか → **十分**。
      現状の追加は不要。後々増やしたくなる可能性には留意する（T-5 で扱う）
- [x] かな・漢字を混ぜたときの濃度の谷 → **谷あり**（かな＋漢字の最大 0.331 と、
      記号の ● 0.633 の間が空く）→ かな・漢字を外す判断と合わせて解消（下記）
- [x] 不要な群はないか → **かな・漢字は不要**（フィラーは記号系で完結させる判断）。
      エッジ用途の文字の追加はユーザーが検討中（保留 → T-5）
- [x] 漢字群の質感 → 濃い領域のフィラーとして**濃度が足りない**（最濃 黒・森 0.331）。
      漢字をフィラーに使わない判断のため、記号（ブロック要素を含む）で濃い側を補う

## 決定事項

- **採用セット = density（27 文字）＋ line（35 文字）の計 62 文字**
- density 群に 11 文字を追加: `▒`(0.189) `▣`(0.224) `▃`(0.312) `◐`(0.350)
  `▄`(0.437) `▀`(0.500) `▅`(0.562) `▆`(0.687) `▛`(0.719) `▇`(0.812) `█`(0.937)。
  ランプの最大の隙間は 0.13（0.81 → 0.94）になった（0.82〜0.94 の間に濃い
  記号はフォント内にない。█ がこのフォントで最も濃い記号）
- **T-1 を改訂**: 「ブロック文字は使わない」→「グリフアトラス描画の等幅セル内で
  あれば、ブロック文字を濃度フィラーに使ってよい」。理由: 非ブロックの記号では
  ■（0.640）が濃度の上限で、0.48〜0.63 と 0.64 超（黒側）が埋められなかった。
  ブロック要素は 1/8 刻みの幾何学的な階段を形成し、アトラス描画では
  T-2 の等幅グリッドに影響しない
- **かな・漢字は採用セットから外す**: 方式 A（D-009 採用）はフィラーに density 群、
  エッジに line 群の直線サブセットのみを使い、かな・漢字は方式 B 専用の候補
  だったため。定義とプリセット `b` は将来の再評価用に残す
- line 群は現状維持。エッジ用文字の追加（例: 太い斜線など）はユーザーの検討事項
  として保留し、T-5（🔶 調整前提）で扱う
- 追加候補の計測は `scan.py`（atlas.py と同一の手順: 64px 描画 → 16×16 へ縮小 →
  平均インク率）で行い、features.json の値と直接比較できるようにした

判断の詳細は docs/decisions/D-010-charset-symbols.md を参照。
