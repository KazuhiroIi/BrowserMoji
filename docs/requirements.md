# ASCII Camera 要件定義書（v0.3）

スマートフォンのブラウザで、カメラ映像をリアルタイムに日本語全角文字のアスキーアート風テキストへ変換して表示する Web アプリの要件を定義する。

- 本書は**プロダクトの要件のみ**を扱う。設計方針・技術選定は [architecture.md](./architecture.md) を参照
- 状態: 🔒確定（変えない土台） / 🔶仮決め（変更しうる） / ❓未決（§9）
- 優先度: **M**=Must / **S**=Should / **C**=Could / **W**=Won't（今回やらない）
- 仕様変更時は、該当 ID の行の状態・優先度・内容を更新する（履歴は git が持つ）

## 1. 目的

| ID | 内容 | 状態 |
|---|---|---|
| G-1 | 利用者が自分のスマートフォンで URL を開くだけで、カメラ映像がリアルタイムにアスキーアート化される体験を提供する | 🔒 |
| G-2 | 映像の変換はすべて端末内（on-device）で完結し、映像・画像を外部に送信しない | 🔒 |
| G-3 | 単純な「輝度 → 文字の濃さ」の対応にとどまらず、勾配（Sobel 等）に基づくエッジ検出と、エッジの向きに沿った線の描画を行う | 🔒 |
| G-4 | ソースコードを公開する | 🔒 |

## 2. 用語

- **セル**: 画面を格子状に分割した 1 区画。1 セルに全角文字 1 文字を表示する
- **グリフアトラス**: 使用する文字を画像化して 1 枚にまとめたもの。端末のフォントに依存せず描画するために使う
- **基準実装**: 処理の正しさの基準とする、最適化しない素直な実装（CPU 版）

## 3. 対象環境

| ID | 内容 | 状態 |
|---|---|---|
| E-1 | iOS の Safari・Chrome、Android の Chrome で動作する | 🔒 |
| E-2 | 古い端末・ブラウザは切り捨てる。対応範囲は、必須機能（`getUserMedia`、WebGL2 など）の有無で判定し、非対応の場合は理由を表示する | 🔶 |
| E-3 | HTTPS で配信する（カメラ利用の要件） | 🔒 |
| E-4 | 縦向き・横向きの両方に対応し、回転しても動作を継続する | 🔒 |

## 4. 性能要件

| ID | 内容 | 状態 |
|---|---|---|
| P-1 | 標準的な近年のスマートフォンで **30fps** を目標とする | 🔶 |
| P-2 | 低スペック端末（2019〜2020 年頃発売のミッドレンジ Android 相当）で **15fps 以上** を維持する | 🔒 |
| P-3 | 現在の fps と処理時間を画面上に表示できる（デバッグ表示） | 🔒 |
| P-4 | 数分間の連続使用で、極端な発熱・動作低下・メモリ増加が起きない | 🔶 |
| P-5 | 初回ロードサイズの目標を設ける（提案: コア機能で 2MB 以下。セグメンテーション用モデルは別読み込み） | ❓ |

## 5. 機能要件

### 5.1 コア機能

| ID | 内容 | 優先度 | 状態 | 受け入れ基準 |
|---|---|---|---|---|
| F-1 | カメラ映像をリアルタイムに取得する。**既定は背面カメラ** | M | 🔒 | 開始操作後、背面カメラ映像が処理に入力される |
| F-2 | 映像を日本語全角文字のアスキーアートに変換して表示する | M | 🔒 | セルごとに全角 1 文字が格子状に表示される |
| F-3 | 輝度に応じた文字の濃淡表現 | M | 🔒 | 暗部と明部で使われる文字の濃さが明確に異なる |
| F-4 | Sobel 等による勾配計算とエッジ検出を行い、勾配の向きに応じた線を描く文字を選ぶ | M | 🔶 | 輪郭が、向きに沿った線状の文字で描かれる |
| F-5 | 解像度（列数）を利用者が変更できる | M | 🔒 | 変更が即座に反映される |
| F-6 | パラメータ調整 UI（§7.2） | M | 🔒 | 操作の結果が即座に表示に反映される |
| F-7 | モノクロ表示 | M | 🔒 | — |
| F-8 | プライバシー表示（映像は端末外に送信されない旨）を、利用開始前に見える位置に表示する | M | 🔒 | 開始前の画面に常に表示される |
| F-9 | エラー表示（カメラ権限の拒否、非対応ブラウザ、カメラ未検出）と復帰方法の案内 | M | 🔶 | 各ケースで原因と対処が表示される |

| ID | 内容 | 優先度 | 状態 |
|---|---|---|---|

## 6. 非機能要件

| ID | 内容 | 状態 |
|---|---|---|
| N-1 | **プライバシー**: 映像・画像を外部へ送信しない。アクセス解析・外部トラッキング・実行時の外部 CDN／外部フォント読み込みを行わない | 🔒 |
| N-2 | **オフライン**: 初回読み込み後は通信なしで動作する（PWA） | 🔶 |
| N-3 | **変更容易性**: 変換処理を段階ごとのモジュールに分け、文字選択のアルゴリズムなどを差し替え可能にする | 🔒 |
| N-4 | **検証可能性**: 基準実装（CPU 版）を残し、最適化実装との出力差を比較できる | 🔶 |
| N-5 | **端末非依存の表示**: 端末のフォント差で表示が崩れない | 🔶 |
| N-6 | **配信**: GitHub Pages で静的配信する | 🔒 |
| N-7 | **ライセンス**: リポジトリのライセンスを明示する。依存物のライセンスと矛盾しないこと（特に F-17 のモデル） | ❓（Q-2） |
| N-8 | **ドキュメント**: `docs/` 配下に Markdown で集約する | 🔒 |
| N-9 | **多言語対応の余地**: UI の文言をコードから分離し、言語ごとの辞書で差し替えられる構造にする（v1 の提供言語は日本語のみ）。表示言語の選択は、後から追加できる構造にしておく | 🔒 |

## 7. 画面・操作

### 7.1 画面フロー

1. **開始画面**: アプリの説明、プライバシー表示（F-8）、「開始」ボタン。カメラ権限の要求は、利用者の操作（ボタン押下）の後に行う
2. **カメラ権限ダイアログ**（ブラウザ標準）。拒否された場合は F-9 のエラー表示
3. **表示画面**: アスキーアートを画面全体に表示。設定パネルの開閉ボタン、（デバッグ時のみ）fps 表示
4. 画面回転に追従して、セルの配置を再計算する

### 7.2 パラメータ調整 UI で扱う項目（初期案）

| 項目 | 内容 | 優先度 |
|---|---|---|
| 解像度 | 列数（行数は画面比から自動計算） | M |
| コントラスト | 輝度の階調の強さ | M |
| エッジの強さ | エッジとして扱うしきい値と、エッジ文字の優先度 | M |
| 白黒反転 | 背景色と文字色の入れ替え | M |
| 文字セット | 使用する文字セットの選択 | S（F-13 と連動） |
| カラー切り替え | モノクロ／カラー | S（F-10 と連動） |

初期値は実験（architecture.md の実験一覧）で決める。

## 8. 文字・表示の方針

| ID | 内容 | 状態 |
|---|---|---|
| T-1 | v1 の文字は日本語の全角文字とする。ブロック文字（▀▄█ など）は使わない | 🔒 |
| T-2 | 1 セル = 全角 1 文字（正方形に近いセル）の等幅グリッドとする | 🔒 |
| T-3 | 背景（文字を置かない部分）は全角スペースで埋める | 🔶 |
| T-4 | 文字セットに含める文字の範囲は、試作で見た目を比較して決める | ❓ |
| T-5 | エッジ用の文字（`／＼｜―` など）の選択方法は、見た目を見ながら調整する前提とする | 🔶 |
| T-6 | 既定の配色は白背景＋黒文字とし、白黒反転で切り替えられる | 🔒 |
| T-7 | 文字セット・エッジ表現は UI の言語とは独立とする（UI の言語を変えても、アスキーアートの表示は変わらない） | 🔒 |
